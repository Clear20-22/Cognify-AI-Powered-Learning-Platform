The 64 realtime checks include domain validation, role/ownership checks, room
capacity/expiry, answer-key privacy, server deadlines, concurrent duplicate
answers, score recovery and bounded socket sends. Tests use the actual mounted
FastAPI app as well as isolated transport fixtures. Real JWT checks cover
unauthenticated access, student host rejection, inactive accounts, expired tokens,
untrusted origins and malformed/oversized frames.

The actual-app integration checks assert question delivery and score/leaderboard
broadcast plus acknowledgement in under one second locally. Network interruption
and reconnect restore the student's original answer and score. All three supported
notification events are delivered privately and replayed; other accounts receive
no history, and clients cannot publish events.

Frontend checks exercise answer locking, acknowledgements for older questions,
manual reconnect after pending commands, unrelated broadcasts during teacher
commands, replaced sockets, per-account saved rooms and notification isolation.
Notification replay is deduplicated and displayed newest first. The global panel
uses one stream independently of room connections.

Validation dependencies are isolated in ignored `.test-deps/`; `node_modules`,
`dist`, credentials and generated bytecode are excluded from the contribution.
Async/transport checks on this Windows host require local socket access outside
the default sandbox. No production database or AI service is needed by the live
integration fixtures.

Existing dependency deprecation warnings remain. Vite reports a non-blocking
bundle-size warning around 503 kB. No dependency upgrades are included in this PR.

## Remaining integration and operational limits

- FR-RT-07 transport/UI is implemented; quiz/assignment owners must publish source
  events through the documented authorized-recipient service API when their
  modules ship. The master TODO deliberately leaves this item unchecked.
- Room state and notification history are process local: one backend worker,
  network reconnect supported, server restart clears live state.
- The deployment owner must proxy `/ws/` with WebSocket Upgrade support for a
  same-origin Nginx deployment. Direct configured-backend use is supported.
- Existing CI runs only `backend/tests`; its owner should add the realtime test
  path. The full suite above was run locally.
- A teammate review is required before merge. This contribution does not merge
  or push directly to `main`.
